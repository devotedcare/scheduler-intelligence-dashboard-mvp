# Scheduler Dashboard — Recent Work (2026-10-06)

**Status: none of this is live.** Everything below is built and demoed on local
git branches only. Nothing has been pushed to `main`, and nothing has been
deployed to the Netlify site. A combined demo of all of it runs locally at
`http://localhost:8899` via the `scheduler-demo` folder on the Desktop — see
*The demo site* at the end of this file for how to start it.

---

## 1. Find Coverage — one shift

**Branch:** `shift-not-listed` → folded into `match-score`

- **Who is not listed, and how close they came.** The calling list only ever
  showed caregivers whose saved Open hours cover the *whole* shift, with no
  way to see why the list was short. A new collapsed section under the list
  now explains every excluded caregiver: **close** (open for part of the
  shift, with their real hours and what's missing, nearest first), **already
  booked** (with when), and counts for gender, unavailable, nothing entered,
  not loaded, and other. Nobody's eligibility changed — this is a read-out.
- **Distance added to the close/booked rows**, in the same wording as the
  calling list ("Camarillo · ~20 mins away").

**Branch:** `match-score`

- **Match score and reasons**, built from the owner's matching-logic spec:
  a % on each row, a relationship pill ("Regular caregiver · 7 visits in 30
  days", "On this client's caregiver list", "New to this client"), and ticked
  reasons ("No schedule conflict", "Drives clients").
- **Three groups**: Best matches / Good matches / Other available, each with
  a one-line description and a coloured left edge.
- **Two new hard filters**: a caregiver recorded as not driving clients is
  now excluded (was a warning only) when the client needs a driver; a
  caregiver whose other visit that day doesn't leave enough travel time to
  reach this one is excluded too, and shown in the not-listed section as a
  booking conflict.
- **Reliability is deliberately left out of the score** — AxisCare has no
  such figure and none is derived yet — and the card says so under the list.
- **The multi-select tick boxes and "Text several at once" bar were
  removed** from this screen (owner's call) — each row keeps its own Call
  and Text.

## 2. Find Coverage — weekly grid

**Branch:** `coverage-working-reason`

- Added a "working a visit that day" reason to the part-of-window list, so a
  caregiver already on a shift reads differently from one who simply hasn't
  entered availability.

## 3. Backup Caregivers

**Branch:** `backup-match-facts`

- Redesigned the whole screen: a verdict edge (good/warn/bad) per card,
  columns instead of a single stack, "Recorded experience", and a staff
  history pulled from AxisCare visits (4/8/12-month lookback) showing
  whether this caregiver has actually worked with this client before.
- Auto-detected requirements from the client's own notes (Female/Male, etc.)
  pre-fill the filters, with an "Advanced settings" summary row.

## 4. Caregiver Record Status — Needs Update

**Branch:** `record-status-tabs`, further simplified on top

- **Cadence moved to its own "No Cadence" tab**; the old inline cadence
  editor is gone from the day panel entirely.
- **"No schedule by month"**: a month picker (switch + stepper + name
  picker) lists every active caregiver with no AxisCare visit and no
  availability entered for the selected month.
- **Needs Update redesigned twice**, ending on the simplest version:
  - *First pass:* every missing profile field became a clickable link, going
    straight to the editor that fills it in (Work Preferences, Skills,
    Experience, or the Profile tab).
  - *Second pass (grouped):* the ~19 bullets collapsed into 3–4 rows, one
    per editor, with pills for the individual fields.
  - *Final pass, after feedback that the grouped version was still busy:*
    **one line per caregiver** — "19 of 20 profile fields missing" plus a
    single **Fill in** button that walks through the editors in order
    (Work Preferences → Skills → Experience → Profile), with the full list
    available behind a "Show what's missing" toggle.
- **Call and Text buttons** added to every card, next to View calendar. Text
  reuses the Find Coverage composer and Quo send, with three message
  templates written for this screen (Update profile details, Ask for
  availability, General check-in) — none of them reference a shift or client.
- **A search box** filters the list by caregiver name or city without
  re-rendering, so it survives the page's 20-second poll.

## 5. Caregiver calendar popup

**Branch:** `record-status-tabs`

- **Select multiple days directly on the calendar grid.** "Select multiple
  days" turns every day into a tick target; ticks survive paging between
  months; "Set availability for N days" hands them to the existing day
  panel's "Selected days" path, which does the actual carve-and-save. This
  is a front door to a feature that already existed but was hard to find —
  it writes nothing by itself.

## 6. Settings — Phone & Text (new)

**Branch:** `settings-quo`

- A new **Settings** section in the nav, one page: **Phone & Text**.
- **Choose which Quo line this computer texts from** — the page lists only
  the agency lines the current "Working as" person is actually a member of
  in Quo (not every line that exists), so nobody is offered a line Quo would
  reject them from.
- **Or use your own number** — texts open in the device's own messaging app
  (an `sms:` link) instead of going through Quo. Clearly one-recipient-only,
  and the page explains that these messages are not saved in Quo or shown on
  Communication Logs.
- **Calling**: Quo's API has no way to place a call, and its deep link for
  dialing from a chosen line is documented as mobile-only. So:
  - **On a phone or tablet**, a Call button now opens the Quo app directly,
    dialing from the line chosen in Settings.
  - **On a computer**, Call stays a plain `tel:` link; the page explains that
    making the Quo desktop app the default handler for phone links is what
    routes it there.
- The choice is per-browser (`localStorage`), never written to the shared
  `scheduler_state` row — one scheduler's pick can't change another's.

## The demo site

All of the above is merged into one local branch, `demo-all`, and served by a
small Node server with made-up sample data (24 "Demo" caregivers, 8 "Sample"
clients, fabricated visits/availability). It never contacts AxisCare,
Supabase, Quo or Anthropic.

```
cd "Desktop\scheduler-demo"
node server.js            (or double-click "Start demo.cmd")
open http://localhost:8899
```

A "DEMO · sample data only" badge sits on every page. A 34-check automated
click-through covers every screen above with no page errors; it has not
clicked every individual button (e.g. a real Quo send has never actually
fired, since the demo server fakes that response).
